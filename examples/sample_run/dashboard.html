System Motivation
Why ML + RL?
❌ Why ML Alone is NOT Enough
  • · Classifies traffic but takes no action
  • · Static weights cannot adapt post-deployment
  • · A prediction without response leaves network exposed
  • · No feedback mechanism for continuous learning
✅ Why RL Closes the Gap
  • · Learns adaptive response policy via reward feedback
  • · Maps (prediction, confidence) → ALLOW/ALERT/BLOCK
  • · Learns through Q-learning updates during training; policy frozen at evaluation
  • · Closed-loop architecture enables self-healing behavior

🤖 Q-Learning Policy
The RL agent learns an adaptive response policy using reward-based feedback. It maps (prediction, confidence) state tuples to optimal network actions through iterative Q-table updates.
State = (prediction, conf_bucket)
conf_bucket = int(confidence × 10)
Actions = ["ALLOW", "ALERT", "BLOCK"]
α=0.1 · γ=0.9 · ε: 1.0 → 0.05 (decay 0.9, train_rl.py) · ε=0 at evaluation
Q[s,a] += α × (reward − Q[s,a]) · terminal per-flow decision
def choose_action(state):
  if random() < epsilon: # explore
    return random.choice(actions)
  return actions[argmax(Q[state])] # exploit

🧠 What the System Learns From Experience

Threat Memory

Stores malicious event context, pattern identity, prior action, response and verification outcome so later decisions can use security history.

Pattern Intelligence

Deterministic behavioral signatures identify NEW, KNOWN and REPEATED malicious behavior without claiming ML clustering.

Defense Reuse

Repeated threats with a previously successful containment can trigger REUSE_DEFENSE / REINFORCE_EXISTING_RESPONSE.

Controlled Learning

Operational policy adapts through memory and recovery. RF retraining and Q-table updates remain controlled, not automatic during inference.
